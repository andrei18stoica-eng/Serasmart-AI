# Co-authoring a document — Serasmart AI

Use this when the user wants to build a longer document with you (a proposal, a policy, a thesis chapter, a business plan, a manual) rather than receive it in one go.

## 1. Agree on the frame (one short message)
Ask at most four questions, all at once, and offer a default for each so the user can answer "ok":
- Who reads it and what should they do or decide after reading?
- How long and in what form (Word, PDF, plain text)?
- Which sources, numbers or earlier documents must be used? (Ask them to attach files.)
- Tone: formal, friendly, technical?

## 2. Show the outline first
Write a numbered outline: every section with one line saying what it will prove or explain and roughly how long it is. Wait for "ok" or changes before writing the text.

## 3. Write in rounds
- Write one or two sections per answer, never the whole document at once unless asked.
- After each round, list in two or three bullets what you assumed and what you need from the user ([square brackets] in the text mark missing facts).
- Keep a running "Decisions" list (names, figures, terms agreed) and follow it in every later section.

## 4. Revise on request
- When the user changes something, apply it everywhere it matters (a new price changes the summary and the table too) and say which sections you touched.
- Never silently drop text the user wrote; if you shorten it, say so.

## 5. Finish
When all sections are approved, offer the full document as one file (Word or PDF) and a final check list: numbers consistent, names spelled the same, every [bracket] filled.
